# AI 生成选题（工作台接入）

> 用途：记录「个人工作台」接入智谱 GLM、在「灵感 → 选题」转化环节做 AI 辅助生成的经验，供后续复用与迭代参考。
> 适用场景：二次元 / coser 赛道 MCN 达人的选题孵化，把碎片灵感快速转成可执行的选题卡。

## 一、为什么在「灵感 → 选题」这步接 AI

灵感（ideas）和选题（topics）之间一直有一道「最后一公里」没打通：灵感是随手记的一句「还原某热门角色妆造」，选题却需要标题、切入角度、目标平台、一句话卖点——光靠手填，转化成本高，很多灵感就烂在列表里。

接 AI 的核心价值不是「自动写」，而是**把灵感到选题的冷启动成本降到最低**：AI 先给一版完整建议，人只做「挑 + 改 + 确认」。这正好补「选题栏要能往下推」的短板。

## 二、技术落地（可复用配方）

- **模型**：智谱 `glm-4-flash`（免费），endpoint `https://open.bigmodel.cn/api/paas/v4/chat/completions`，兼容 OpenAI 格式，`Authorization: Bearer <key>`。
- **密钥安全**（关键坑）：密钥**绝不放在项目目录内**。因为工作台的 `server.js` 是「按 ROOT 路径静态托管 + 本地写入 API」架构，`config/`、`data/` 下的文件会被 `GET /config/ai.json` 直接读走。正确做法是放项目目录之外（如 `~/.workbuddy/workbench-ai.json`），并在静态托管里加敏感文件正则拦截（`ai.json` / `.ai-key.json` / `workbench-ai.json` → 403）做双保险。
- **后端接口**：`POST /api/ai/angle`，收 `{idea}`，返回结构化 `{title, angles[], platforms[], pitch}`。用 Node 原生 `https.request`（零第三方 SDK），30s 超时，未配 Key 时优雅降级返回 `{ok:false, error:'AI 未配置'}`。
- **前端交互**：转化表单加「✨ AI 生成」按钮（仅转化场景显示），生成后先出「建议卡片」，**点「采纳」才填进表单**，仍可手动改。原则：**AI 只做建议、不直接改数据**。
- **prompt 要点**：要求 AI 返回固定 JSON 结构；返回前做字段规范化（platforms 只留抖音/小红书/B站/微博四平台、angles 限 3 条），避免模型乱输出污染多选字段。

## 三、实测效果（真实调用）

输入灵感「还原某热门二次元角色的妆造」，`glm-4-flash` 返回：

| 字段 | AI 生成 |
|---|---|
| 标题 | 还原热门角色妆容秘籍 |
| 角度 | 角色背景故事解析 / 妆造细节拆解教学 / 粉丝互动妆造挑战赛 |
| 平台 | 抖音、微博、B站 |
| 卖点 | 揭秘热门角色妆容，教学互动，粉丝挑战，还原二次元魅力！ |

## 四、可继续迭代的方向

- **更网感**：调 prompt 让标题更符合平台调性（小红书要「教程/避雷/平替」词，抖音要反差钩子）。
- **多候选**：一次给 3 个标题候选让人挑，而不是单一标题。
- **结合赛道知识**：把本知识库的「二次元赛道打法」「平台规则与雷区」作为 prompt 上下文注入，让生成的选题天然合规、贴合人设，而不是通用模板。

## 五、教训沉淀

1. **「点了就变状态」是交互 bug 不是功能缺失**：转化时若表单预填了内容，用户会习惯性直接点提交，误以为「没机会编辑」。要给足「这是可编辑表单」的暗示 + 副作用说明。
2. **验证要「真实调用」而非只看代码**：AI 接口第一次用沙箱 fetch 报 exit 23（代理问题），换 curl 直连才通——沙箱网络和真实环境不一致，联调要落到能跑通的那条链路。
3. **密钥安全是接入 AI 的第一道闸**：先确认静态托管范围再决定密钥放哪，而不是先把 Key 写进 config 再补拦截。
